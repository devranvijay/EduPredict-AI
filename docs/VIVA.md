# Viva preparation

**Q1. What does your network do?** Maps 25–33 student features to a final mark (0–100) through 16 ReLU hidden neurons and one linear output neuron. Regression, trained with MSE.

**Q2. Why ReLU in the hidden layer and linear at the output?** ReLU adds non-linearity (without it, the network collapses to a linear model) and avoids vanishing gradients; a linear output allows any real-valued mark.

**Q3. Explain forward propagation.** `z1 = X·W1 + b1`, `a1 = max(0, z1)`, `ŷ = a1·W2 + b2`. The dashboard's "Inside the network" panel shows these numbers for one student.

**Q4. Explain backpropagation.** Chain rule from loss to weights: `dz2 = 2(ŷ−y)/n`, `dW2 = a1ᵀ dz2`, `dz1 = (dz2·W2ᵀ) ⊙ 1[z1>0]`, `dW1 = Xᵀ dz1`. Bias gradients are column sums.

**Q5. How do you know backprop is correct?** Compared to central finite differences: max relative error between 2e-8 and 1.3e-7. I skip samples near ReLU's kink at 0 because the function isn't differentiable there (an early run showed a spurious 0.3 error from exactly that).

**Q6. Gradient descent and learning rate?** `θ ← θ − lr·∇L`, mini-batches of 128, lr 0.01. Too large diverges; too small is slow. Early stopping on validation loss prevents overfitting.

**Q7. Is backprop the same as the Delta rule?** No. The Delta rule updates a single neuron from its output error; backprop propagates errors through hidden layers using the chain rule and ReLU derivatives. The Delta rule is the single-layer special case of the idea.

**Q8. Explain McCulloch–Pitts, Hebb and Delta in your project.** MP: binary inputs, fixed weights, fires if sum ≥ threshold (AND T=2, OR T=1). Hebb: Δw = x·y, strengthens weights for co-active input/output. Delta: Δw = η(t−y)x, reduces error step by step. All three are in the "ANN fundamentals lab" tab.

**Q9. Where does your data come from?** It is synthetic: generated by `src/synthetic_data.py` from rules I wrote (ability, motivation, attendance, study hours, sleep, stress, tutoring and so on, plus noise). It is not real student data, and I say so on the dashboard and in the report.

**Q10. Why use synthetic data?** The public UCI data I started with has no attendance or assignment columns, and I did not want to fabricate them silently. A clearly labelled generator gives richer factors and documented ground truth. The trade-off is that results show the pipeline works, not how real students behave.

**Q11. Why three models?** They differ in when inputs are known. `early` (25 inputs) is usable before the term; `during_term` (31) adds attendance, study hours, assignments, quizzes; `late` (33) adds mid-term and assignment average. Test RMSE: 8.36, 6.26, 3.77 (baseline 16.52).

**Q12. Isn't `late` cheating?** Mid-term and assignments are legitimate earlier information, but they are 40% of the final mark by construction, so R² 0.95 is partly built in. `final_exam_score`, which is 60% of the mark, is excluded entirely, and a test enforces it.

**Q13. How did you avoid data leakage?** Scaling statistics from train only; test set used once at the end; split grouped by `student_id` because each student has 6 rows; target-derived columns (`final_exam_score`, `grade_letter`, `passed`) are never inputs.

**Q14. Is 16 neurons optimal?** No evidence. Validation RMSE for 2/4/8/16/32 neurons was almost identical (e.g. 6.07–6.18 for `during_term`); 2 neurons did as well as 32, which suggests the simulated target is close to linear. The Delta-rule experiment backs that up: the best straight line on the 19 numeric inputs gets test RMSE 6.28 versus 6.26 for the 16-neuron network. I kept 16 as the specified start.

**Q15. What does R² = 0.86 mean?** (`during_term`) The model explains about 86% of the variance in test marks; MAE 4.99 means an average error of about 5 marks out of 100.

**Q16. Can the what-if tool tell a student what to change?** No. It shows how the model's output moves; it is not causal evidence. Some inputs such as `gender` or `class_size` have no effect on marks by construction.

**Q16b. What does your Delta-rule demo on the student data show?** One linear neuron learns `w ← w + η(target − output)x` one student at a time. Within a few hundred students its error falls from about 16 (predict the mean) to near the best straight line (about 7.8 with attendance, quiz and study hours). Its weights read as "marks per +1 SD of input" (quiz score about 11.7, attendance about 2.5). It cannot beat the best straight line, and a large learning rate makes it bounce instead of settle.

**Q17. Main limitations?** Synthetic data, single split and seed, no confidence intervals, `late` partly contains the answer, near-linear data, output not bounded.

**Q18. How would you improve it?** Validate on real data, cross-validate over seeds, add L2/dropout and tune depth and learning rate, run an input-ablation study, add uncertainty estimates.

**Q19. Why did `late` stop at 300 epochs?** It hit the epoch cap before early stopping triggered, so it could be slightly under-trained; a longer run might lower its error a little.
